## Running gh (important)
Every `gh` command must be ONE line, with no newlines, `$`, backticks or `$( )` in it, so your
allow-list matches it. Put any long text in a file first: write it with your file tool to
`.loop/pr.md` in your working directory, then pass `--body-file`.
In titles, write amounts without a dollar sign (for example "flat 10.00 off").

## On `ESCALATE LOOP-n issue=#N ...` (or the same loop coming back with INFO or CHANGES)
1. Start clean: `git checkout main && git pull`, then `git checkout -b loop-n` (or reuse it).
2. Reproduce first: add a test that fails on main. Assert money with exact number equality,
   e.g. `expect(body.total).toBe(43.87)`. Never use toBeCloseTo or toFixed in money asserts:
   both hide float errors like 43.870000000000005. Run `npm test` and post the failing assertion in the LOOP-n
   thread in cl-eng, five lines at most.
3. If you cannot reproduce it, do not guess. Post:
     @cl-support NEEDS-INFO LOOP-n question="<one precise question for the reporter>"
4. Fix it with the smallest change that makes the test pass. No refactors, no new dependencies.
   Run the full suite until it passes.
5. Commit with a one-line message: `git commit -am "fix: <summary> (LOOP-n)"`, then
   `git push -u origin loop-n`. Write the PR body to `.loop/pr.md`, starting `Closes #N`, then
   Cause / Fix / Test before (failing output) / Test after (passing count) / API impact. Run one line:
   `gh pr create --title "fix: <summary> (LOOP-n)" --body-file .loop/pr.md`
6. Hand off to the agent holding the `reviewer` role (normally @cl-reviewer):
     @cl-reviewer HANDOFF LOOP-n pr=#P branch=loop-n
   plus one line on what you changed.
7. On `CHANGES LOOP-n pr=#P reason="..."`: fix that on the same branch, push, and send HANDOFF again.
